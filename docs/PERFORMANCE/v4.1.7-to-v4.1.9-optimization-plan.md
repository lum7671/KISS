## 🔍 기술 배경

### ProfileManager & ActionPerformanceTracker의 역할
- **ProfileManager**: 5초 간격 시스템 메트릭 수집 (메모리, CPU, 스레드, GC)
- **ActionPerformanceTracker**: 사용자 액션별 성능 스냅샷 (검색, 스크롤, 터치)
- **목적**: Throttling/Lazy Init 최적화 전후 성능 비교를 위한 정량적 데이터 수집

### 측정 지표
| 지표 | 현재 | 목표 | 측정 방법 |
|------|------|------|----------|
| 콜드 스타트 | 3000-4000ms | 2000-3000ms | Provider 로드 시간 합계 |
| UI 표시 시간 | 2500-3000ms | 1000-1500ms | MainActivity.onCreate ~ 표시 |
| 메모리 사용 | 250-350MB | 200-300MB | 프로파일 CSV max_heap |
| onResume 리로드 | 매번 | 60% 이상 스킵 | Throttling 이벤트 로그 |

## 🚀 Phase 1.1: Refresh Throttling 구현 (4-6시간)

### 목표
onResume 호출 시 2초 내 중복 리로드 방지 → 배터리 효율 개선, 불필요한 작업 90% 감소

### 설계

```
현재:
onResume → 항상 리로드 → 350ms 소요 → 배터리 ↓

개선:
onResume → Throttling 체크 → 
  ├─ OK (2초 경과) → 리로드 → 350ms
  └─ NO (2초 미경과) → 스킵 → <5ms (90% 경우)
```

### 작업 항목

#### ✅ Step 1.1.1: DataHandler에 Throttling 로직 추가

**파일**: `app/src/main/java/fr/neamar/kiss/DataHandler.java`

**위치**: `shouldUpdateOnResume()` 메서드 (라인 99-101)

**구현**:
```java
private volatile long lastReloadTime = 0;
private static final long RELOAD_THROTTLE_MS = 2000;  // 2초

public boolean shouldReload() {
    long now = System.currentTimeMillis();
    if (now - lastReloadTime < RELOAD_THROTTLE_MS) {
        ProfileManager.getInstance().logEvent(
            "RELOAD_THROTTLED",
            "reason:frequency_limit,elapsed_ms:" + (now - lastReloadTime)
        );
        return false;  // 스킵
    }
    lastReloadTime = now;
    return true;  // 리로드 진행
}
```

#### ✅ Step 1.1.2: MainActivity에서 Throttling 호출

**파일**: `app/src/main/java/fr/neamar/kiss/MainActivity.java`

**메서드**: `onResume()` 또는 `handleDataUpdateOnResume()`

**추가**:
```java
// onResume에서

if (!dataHandler.shouldReload()) {
    if (BuildConfig.DEBUG) {
        Log.d(TAG, "Reload throttled - too frequent");
    }
    return;  // onResume 처리 종료
}

// 기존 로직 계속 진행
```

**측정 지점**:
```java

// ... 리로드 로직 ...

```

## 🎯 Phase 1.2: Lazy Provider Initialization (6-8시간)

### 목표
필수 제공자(AppProvider)만 콜드 스타트에 로드, 나머지는 첫 검색 시 지연 로드 → 초기 응답성 50% 개선

### 설계

```
현재:
앱 시작 → AppProvider (1s) + ContactsProvider (1s) + ShortcutsProvider (1s) 
        → 모두 완료 후 UI 표시 (3s+)

개선:
앱 시작 → AppProvider (1s) → UI 표시 (1s+)
       → ContactsProvider (백그라운드, 1s)
       → ShortcutsProvider (백그라운드, 1s)
```

### 작업 항목

#### ✅ Step 1.2.1: Provider에 Lazy 기능 추가

**파일**: `app/src/main/java/fr/neamar/kiss/dataprovider/Provider.java`

**추가 필드**:
```java
private boolean lazyInit = false;
private volatile boolean isInitialized = false;

public void setLazyInit(boolean lazy) {
    this.lazyInit = lazy;
}
```

**추가 메서드**:
```java
protected synchronized void ensureLoaded() {
    if (!isInitialized && lazyInit) {
        Log.i(TAG, "Lazy loading triggered for " + this.getClass().getSimpleName());
        
        ProfileManager.getInstance().logEvent(
            "LAZY_LOAD_TRIGGERED",
            "provider:" + this.getClass().getSimpleName()
        );
        
        this.reload();  // 첫 로드
        isInitialized = true;
    }
}
```

**기존 onCreate() 수정**:
```java
@Override
public void onCreate() {
    super.onCreate();
    
    if (!lazyInit) {
        this.reload();  // 즉시 로드 (AppProvider)
    } else {
        Log.i(TAG, "Lazy init enabled for " + this.getClass().getSimpleName());
        // 실제 로드는 ensureLoaded()로 지연
    }
}
```

#### ✅ Step 1.2.2: DataHandler에서 제공자별 전략 설정

**파일**: `app/src/main/java/fr/neamar/kiss/DataHandler.java`

**메서드**: `connectToProvider()` (라인 ~150-200 추정)

**수정**:
```java
protected void connectToProvider(final String name, final int counter) {
    // ... 기존 바인딩 코드 ...

#!/usr/bin/env python3
import pandas as pd
import sys
from pathlib import Path

def analyze_profile_log(csv_path):
    """프로파일 로그 분석"""
    df = pd.read_csv(csv_path)
    
    print("=== KISS Profile 성능 분석 ===")
    print(f"파일: {csv_path}")
    print(f"기간: {df['timestamp'].min()} ~ {df['timestamp'].max()}")
    print()
    
    # 메모리
    print("📊 메모리 사용량")
    print(f"  최대: {df['heap_used_mb'].max():.1f}MB")
    print(f"  평균: {df['heap_used_mb'].mean():.1f}MB")
    print(f"  증가율: {(df['heap_used_mb'].iloc[-1] - df['heap_used_mb'].iloc[0]):.1f}MB")
    print()
    
    # CPU & 스레드
    print("💻 CPU & 스레드")
    print(f"  평균 CPU: {df['cpu_usage_percent'].mean():.1f}%")
    print(f"  최대 스레드: {df['thread_count'].max()}")
    print(f"  평균 스레드: {df['thread_count'].mean():.0f}")
    print()
    
    # GC
    print("🗑️  가비지 컬렉션")
    print(f"  GC 횟수: {df['gc_count'].max() - df['gc_count'].min()}")
    print()

if __name__ == '__main__':
    if len(sys.argv) < 2:
        print("사용법: python3 analyze_profile.py <csv_file>")
        sys.exit(1)
    
    analyze_profile_log(sys.argv[1])
```
