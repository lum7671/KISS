# v4.2.2 긴급 버그 수정 보고서

**날짜:** 2025-10-16  
**버전:** 4.2.2 (422)  
**이전 버전:** 4.2.1 (421)

## 문제 요약

v4.2.1에서 Edge-to-edge 디스플레이 지원을 Android 13+ 전체에 적용하면서 발생한 UI 레이아웃 문제들:

### 1. Back 버튼 누를 시 빈 화면 표시
- **증상:** KISS 런처에서 back 버튼을 누르면 빈 화면이 나타남
- **원인:** `handleBackPress()` 로직이 `finish()` 호출 전에 조건을 제대로 체크하지 않음
- **수정:** Early return 패턴으로 로직 개선

### 2. 시스템 네비게이션 버튼과 런처 버튼 겹침
- **증상:** 시스템 뒤로가기 버튼이 런처의 검색 버튼과 메뉴 버튼을 가려서 터치 불가능
- **원인:** `WindowCompat.setDecorFitsSystemWindows(false)` 설정으로 시스템 바 영역까지 앱이 그려지지만, 레이아웃에 적절한 insets padding 없음
- **수정:** Edge-to-edge를 Android 15+에만 적용하도록 원복

### 3. 키보드가 검색 결과 목록을 가림
- **증상:** "play" 검색 시 목록이 키보드 뒤로 가려짐. Back 버튼을 눌러야 겨우 보임
- **원인:** 위와 동일 - 시스템 insets 처리 부재
- **수정:** 위와 동일

## 기술적 분석

### 근본 원인
```java
// v4.2.1의 문제 코드
WindowCompat.setDecorFitsSystemWindows(getWindow(), false);
```

이 설정은 앱이 시스템 바(상태바, 네비게이션 바) 뒤까지 그려지도록 하지만, 이를 위해서는:
1. 레이아웃에 `WindowInsets` 리스너를 추가
2. 각 뷰에 적절한 padding/margin을 동적으로 적용
3. 키보드 insets도 별도 처리 필요

이러한 작업들이 누락되어 UI가 시스템 요소에 가려지는 문제 발생.

### 적용된 해결책

#### 1. Edge-to-edge 범위 축소
```java
// v4.2.0의 원래 코드로 복원
if (android.os.Build.VERSION.SDK_INT >= Build.VERSION_CODES.VANILLA_ICE_CREAM) {
    getWindow().setStatusBarColor(android.graphics.Color.TRANSPARENT);
    getWindow().setNavigationBarColor(android.graphics.Color.TRANSPARENT);
    getWindow().getDecorView().setSystemUiVisibility(
        View.SYSTEM_UI_FLAG_LAYOUT_STABLE |
        View.SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN |
        View.SYSTEM_UI_FLAG_LAYOUT_HIDE_NAVIGATION
    );
}
```

**이유:**
- Android 15+는 자동으로 edge-to-edge를 처리하는 새로운 메커니즘 제공
- 구형 API(deprecated flags)를 사용하더라도 Android 15에서는 안전하게 동작
- Android 13-14에서는 전통적 레이아웃 유지

#### 2. Back Press 로직 개선
```java
// Before (v4.2.1)
private void handleBackPress() {
    if (mPopup != null) {
        mPopup.dismiss();
    } else if (isViewingAllApps()) {
        displayKissBar(false);
    } else {
        clearSearchText();
    }
    
    if (!isKissDefaultLauncher()) {
        finish();
    }
}

// After (v4.2.2)
private void handleBackPress() {
    if (mPopup != null) {
        mPopup.dismiss();
        return;  // 여기서 종료
    }
    
    if (isViewingAllApps()) {
        displayKissBar(false);
        return;  // 여기서 종료
    }
    
    clearSearchText();
    
    // 기본 런처가 아닐 때만 finish()
    if (!isKissDefaultLauncher()) {
        finish();
    }
}
```

**개선점:**
- Early return 패턴으로 명확한 제어 흐름
- 각 조건에서 처리 후 즉시 종료하므로 의도치 않은 `finish()` 호출 방지
- 코드 가독성 향상

#### 3. 불필요한 import 제거
```java
// 제거된 imports
import androidx.core.view.WindowCompat;
import androidx.core.view.WindowInsetsControllerCompat;
```

## 향후 계획

### Edge-to-edge 완전 지원 로드맵

현재는 Android 15+에서만 제한적으로 지원하지만, 향후 전체 지원을 위해서는:

1. **Phase 1: WindowInsets 처리 구조 설계**
   - `main.xml` 레이아웃 분석
   - Insets 적용이 필요한 뷰 식별
   - `ViewCompat.setOnApplyWindowInsetsListener()` 구조 설계

2. **Phase 2: 레이아웃 수정**
   - `searchEditLayout`에 bottom insets 적용 (네비게이션 바 회피)
   - `widgetLayout`에 top insets 적용 (상태바 회피)
   - `resultLayout`의 ListView에 키보드 insets 적용

3. **Phase 3: 동적 패딩 적용**
   ```java
   ViewCompat.setOnApplyWindowInsetsListener(searchEditLayout, (v, insets) -> {
       Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
       Insets ime = insets.getInsets(WindowInsetsCompat.Type.ime());
       
       v.setPadding(
           v.getPaddingLeft(),
           v.getPaddingTop(),
           v.getPaddingRight(),
           systemBars.bottom + ime.bottom
       );
       
       return insets;
   });
   ```

4. **Phase 4: 테스트 및 점진적 롤아웃**
   - Android 13에서 먼저 테스트
   - Beta 사용자에게 배포
   - 피드백 수집 후 전체 배포
